# Specification process

Published-version RFC files are archival technical baselines. Record ambiguities in `errata/`, use `profiles/` for explicitly provisional implementation choices, and publish new normative semantics as a new reviewed document version. Technical edits need a motivation, affected requirements, compatibility assessment, migration plan and conformance vectors.

Use statuses: draft → public review → proposed standard → stable, with withdrawn/deprecated when necessary. Only a recorded maintainer decision changes status. The inherited phrase “Standards Track” indicates this project's process; no external standards body's approval is implied.

Editors maintain stable requirement identifiers and normative citations. Each implementation release states the RFC versions, profile revision, supported topology, and optional features it implements. Unknown, blocked and unsupported requirements stay visible. A green build is not a conformance designation.
