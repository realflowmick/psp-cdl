# Implementation roadmap

The repository setup is milestone M0. The following milestones define implementation work and acceptance gates, not completed security features. The [current progress and actionable backlog](docs/backlog.md) records merged slices, remaining issues and dependencies. GitHub issues #2-#9 remain open milestone trackers; `.github/bootstrap-issues.json` is the original provisioning seed, not the current progress register.

**Current work:** #35 now has an [API 1.0.0 adoption candidate](specs/api/RFC-PSP-API-v1_0_0-candidate.md), combined contracts and an explicit public-review/decision record. Normative adoption requires the comment period and recorded lead disposition. #37/#38 now have [paired opt-in lifecycle and security-tool implementations](https://github.com/realflowmick/psp-cdl/pull/57) with shared contracts and transport cases; review and #35 normative API adoption remain pending. #33 has a [buffered-provider implementation PR](https://github.com/realflowmick/psp-cdl/pull/53) awaiting review. The [requirements/parser review](specs/reviews/PSP-CDL-REVIEW-0.1.md) and [API/editorial proposal](specs/errata/PSP-CDL-EDITORIAL-0.1.md) now supply draft material for #34/#35; normative adoption remains pending. #36 differential fuzzing and #39 isolated fixture servers have implementation PRs awaiting review. Streaming remains unsupported until its [separate streaming contract (#44)](https://github.com/realflowmick/psp-cdl/issues/44) is implemented and tested. No milestone completion gate is waived.

The signature portion of M1 is specified by PSP Core 3.2.0 and [PSP Signature Profile 2.0](specs/profiles/PSP-SIGNATURE-2.0.md), with independently checked Node/Python fixtures. [CDL Deterministic Policy Profile 1.0](specs/profiles/CDL-DETERMINISTIC-1.0.md) and [PSP Trust and Enforcement Profile 1.0](specs/profiles/PSP-TRUST-1.0.md) now specify CDL inheritance, finite policy tables, trust and topology assumptions. Every CDL Appendix B.2/B.3 row is mapped; all 315 policy/trust vectors now execute against both reusable library adapters. M1 still needs adjudication of the expanded requirement inventory and acceptance of the parser-contract review; no complete conformance claim is available.

The first M2 slice is implemented as reusable TypeScript/Python libraries: bounded PSP/CDL codecs, object/JSON/markup round trips, signature/key/time validation, finite policy evaluation and shared profile adapters. The [API guide](docs/library-api.md) documents supported representations and limits. Both languages pass 511 shared checks plus direct two-way interchange and isolated package checks. This is experimental, scoped profile coverage; bounded sustained fuzzing now has infrastructure; broader RFC grammar review and independent security review remain open.

The first read-only M3 slice implements [draft authenticated HTTP/MCP security services](docs/service-api.md) on the reusable libraries, including operation-bound verification and host-owned policy evaluation. Both languages pass 33 shared service cases and real mixed-language HTTP/stdio checks. The [stateful library foundation](docs/persistence.md) adds tenant/owner-scoped sessions, immutable nodes, atomic versioned updates and checkpoint consumption on a replaceable SQLite backend. Both languages pass 42 shared state cases, bidirectional file/token interchange, abrupt-exit recovery and mixed-language races. The opt-in [workflow API](docs/workflow-api.md) connects six authenticated HTTP/MCP operations to host transition authorization, private checkpoint-token handoff and session-bound operation issuance/invalidation. It adds 41 shared scenarios and real workflow mutations in both language directions.

The first M4 [MCP dispatch gate](docs/mcp-dispatch.md) uses these primitives for authenticated host registrations, namespaced read-only routing, exact node affinity, CDL dispatch/release checks, bounded schemas and output provenance. Shared scenarios compare real local tool calls and suppressed output in both languages; optional shared owner coordination covers same-process workflow mutations. [MCP stdio mediation](docs/mcp-stdio.md) now connects a launcher-authenticated caller through that gate to a pinned downstream process. It adds 34 shared process scenarios, observed discovery-drift and bypass checks, bounded I/O and nine real three-process chains in each language direction. [Authenticated Streamable HTTP](docs/mcp-http.md) adds host-owned resource credentials, verified TLS, owner-bound transport sessions and concurrent cancellation with buffered JSON/SSE output. It adds 29 shared boundary scenarios, 42 real mixed-language HTTP/TLS gated calls and eight full HTTP caller/proxy/tool chains. [Host-approved revision refresh](docs/mcp-revision.md) adds an opt-in remote precondition protocol, process-local execution leases and idle gate replacement, with 23 shared revision vectors and 36 mixed-language stdio/HTTP checks. **M3 and M4 remain incomplete.** The first M5 [buffered model/tool loop](docs/llm-loop.md) now uses mock providers, signed host-bound system prompts, transcript-wide CDL checks, the existing dispatch gate and buffered final authorization. Its 69 shared cases compare actual calls, suppressed output and provider-visible transcripts. The opt-in [durable loop](docs/llm-durable.md) adds atomic state/answer receipts, host-approved completion, explicit infrastructure lockdown and current-policy recovery. Its 62 shared cases are paired with SQL rollback, process restart and mixed-language commit-race checks. The opt-in [prompt refresh loop](docs/llm-refresh.md) now adds signed expiration/interval triggers, host compatibility approval, durable version floors and atomic turn counters, with 64 shared cases, eight version comparisons, restart/recovery chains and five mixed-language write races. The opt-in [completion redirect](docs/llm-redirect.md) adds atomic source completion and same-owner target creation with retained CDL evidence, transfer authorization and recovery. Shared boundary cases and mixed-language restart/commit races cover this draft slice. The opt-in [scoped continuation](docs/llm-scoped.md) replaces the SYSTEM prompt, enforces host boundary decisions and atomically persists answers or hard violations while keeping completed workflow state frozen. Its 57 shared cases, SQL rollback/owner-reservation tests and two-way restart plus three commit races cover this experimental slice. M5 remains incomplete: live-provider opt-in is next; streaming needs a separate gating contract. Adaptive/checkpoint triggers and degraded continuation require separate contracts. OAuth authorization/token acquisition remains a host integration. M3 lifecycle and scan/decrypt/process now have opt-in implementation drafts pending review; normative API adoption remains open. PostgreSQL, mutating tools and outbox/dispatch recovery require separate contracts and tests.

The opt-in [MCP prompt refresh adapter](docs/llm-mcp-refresh.md) now discovers a host-approved refresh tool over stdio or authenticated HTTP. Owner/session pinning and exact schemas constrain the host-only exchange; the existing loop still verifies signatures, scope, freshness, version continuity and compatibility. It adds 29 shared cases, seven loop cases per language and 32 mixed-language transport calls. A managed signing service, custom URLs and additional refresh triggers remain pending.

The redirect slice adds 42 shared scenarios plus SQL rollback, owner-reservation cancellation, transaction-expiry, two-way restart/hot-journal recovery and two mixed-language commit races. It initializes target state for a separately authorized host; automatic target inference and refresh/redirect composition remain unsupported.

## Execution order

The selected #36 slice now supplies [seeded differential fuzzing](docs/differential-fuzzing.md), shared regression expectations and two-way wire exchange for existing profiles. Sustained CI is bounded and reproducible; unreviewed RFC grammar changes remain blocked on #34.

The selected #39 slice adds [isolated governed/adversarial MCP fixtures](evaluation/FIXTURE-SERVERS.md), observed reads/exports, signed malicious content and an explicit successful bypass control. These are evaluation infrastructure; no effectiveness study or full workflow conformance is claimed.

1. **Add a buffered provider adapter.** [#33](https://github.com/realflowmick/psp-cdl/issues/33) defines paired adapters, host-owned credentials and authority, bounded I/O, explicit budget/cancellation controls and offline fake-provider cases. Live smoke runs require separate operator opt-in; this task does not enable streaming.
2. **Close standards and core coverage gaps in parallel.** Complete the [normative inventory and parser review (#34)](https://github.com/realflowmick/psp-cdl/issues/34), resolve [API/editorial errata (#35)](https://github.com/realflowmick/psp-cdl/issues/35), and extend [differential fuzzing and reviewed grammar coverage (#36)](https://github.com/realflowmick/psp-cdl/issues/36). Preserve published baselines and explicit blocked/unsupported outcomes.
3. **Complete service and mediation contracts.** The [backlog](docs/backlog.md#remaining-work) separates lifecycle operations, remaining security tools, isolated test servers, PostgreSQL, distributed coordination, mutating dispatch recovery and host OAuth integration. Define shared contracts and synthetic vectors before changing behavior in either language.
4. **Extend LLM modes through separate contracts.** Track [streaming (#44)](https://github.com/realflowmick/psp-cdl/issues/44), [completion/refresh composition (#45)](https://github.com/realflowmick/psp-cdl/issues/45) and [scoped tools/revocation (#46)](https://github.com/realflowmick/psp-cdl/issues/46) independently. [Additional refresh/signing integrations (#47)](https://github.com/realflowmick/psp-cdl/issues/47) first need a scope decision; a hosted signing service is not a prerequisite for using the libraries.
5. **Run full workflow conformance and effectiveness work.** Build the [topology matrix harness (#48)](https://github.com/realflowmick/psp-cdl/issues/48), then [preregister and run the study (#49)](https://github.com/realflowmick/psp-cdl/issues/49). Measure prohibited actions and useful benign completions across controls and mixed-language deployments, with independent grading and negative results.
6. **Meet the reviewed release gate.** Prepare [repeatable artifacts and compatibility documentation (#50)](https://github.com/realflowmick/psp-cdl/issues/50), obtain [independent security review and a recorded release decision (#51)](https://github.com/realflowmick/psp-cdl/issues/51), and keep publication disabled until that gate is satisfied.

Each linked issue has acceptance criteria and dependencies. The milestone trackers retain completed slices and remain open until their gates are met. Queue order does not assign maintainers or due dates; no schedule, success rate, full conformance or production readiness is asserted by this roadmap.

The opt-in [session lifecycle draft](docs/lifecycle.md) adds owner-scoped listing, cancellation and bounded policy-approved payload cleanup in both languages. Checkpoint/operation invalidation, replay tombstones and retained metadata have explicit contracts. This #37 working slice requires review; it does not complete M3 or claim physical erasure.

The opt-in [security tools draft](docs/security-tools.md) adds authenticated scan/decrypt/process in both languages, host-owned AES-GCM key/zone grants and buffered CDL plaintext release. Its 62 shared cases and real two-way HTTP/stdio checks cover all eleven required tool names as draft counterparts. #35 normative API adoption and unsupported encryption forms remain open; this does not complete M3.
